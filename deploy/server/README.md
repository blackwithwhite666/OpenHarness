# ohmo server provisioning (93.77.160.211)

Version-controlled copy of the **hand-provisioned** setup for the ohmo personal-agent
server. Before this dir these scripts/units lived only in `$HOME` on the VM, so a VM
recreate would have lost everything. Reproduce the box by cloning this repo and
following the run order below.

The VM base (Ubuntu 24.04 noble) comes from cloud-init; everything here is the
application layer on top. There is no ansible/config-management — these are
idempotent shell scripts plus user-level systemd units.

## Layout

- `scripts/` — provisioning + ops scripts (run from `$HOME`, as the `blackwithwhite` user):
  - `provision_browser.sh` — stage 1: apt-install google-chrome-stable + KasmVNC (latest noble .deb) + fluxbox/dbus.
  - `stage2a_kasmvnc.sh` — stage 2a: write `~/.vnc/kasmvnc.yaml` + `~/.vnc/xstartup`, generate the kasm web password (random, at runtime), start `vncserver :1`.
  - `stage2b_fix_ssl.sh` — stage 2b: user-owned self-signed TLS cert so KasmVNC under the user systemd manager doesn't need the root-owned snakeoil key.
  - `cdp-healthcheck.sh` — watchdog: curl `:9222/json/version`; if Chrome/CDP is down, restart `kasmvnc-chrome.service` and reattach the `browser-cli` daemon. Driven by `cdp-healthcheck.timer`.
  - `dropbox_apply_excludes.sh` — applies the selective-sync exclude list and stops Dropbox if the disk gets low.
- `systemd/` — user units (install to `~/.config/systemd/user/`):
  - `kasmvnc-chrome.service` — the headful Chrome + KasmVNC (CDP `127.0.0.1:9222`, VNC `127.0.0.1:6080`). NOTE: `Type=forking`, MainPID = Xvnc; Chrome is a grandchild from `xstartup`, so a Chrome-only death is invisible to `Restart=on-failure` — that's why `cdp-healthcheck.timer` exists.
  - `cdp-healthcheck.{service,timer}` — runs the watchdog every 2 min (+ 1 min after boot).
  - `ohmo-gateway.service` — the OpenHarness ohmo Telegram gateway (`ohmo gateway run`).
  - `worfalomey-token-refresh.{service,timer}` — refreshes the worfalomey MCP OAuth token (TTL 1h) and restarts the gateway.
  - `dropbox.service` — Dropbox daemon.
- `vnc/` — `xstartup` (launches fluxbox + `google-chrome-stable --remote-debugging-port=9222`) and `kasmvnc.yaml`.

## Run order (fresh VM)

```bash
# as blackwithwhite, from $HOME
bash provision_browser.sh            # stage 1 (apt; needs sudo)
bash stage2a_kasmvnc.sh              # stage 2a (prints the kasm WEB_PASSWORD — save it)
bash stage2b_fix_ssl.sh             # stage 2b

# install user units
mkdir -p ~/.config/systemd/user ~/.local/bin
cp systemd/*.service systemd/*.timer ~/.config/systemd/user/
cp scripts/cdp-healthcheck.sh ~/.local/bin/ && chmod +x ~/.local/bin/cdp-healthcheck.sh
systemctl --user daemon-reload
systemctl --user enable --now kasmvnc-chrome.service cdp-healthcheck.timer dropbox.service

# ohmo gateway (installed separately via pipx from the deploy branch):
pipx install --force "git+https://github.com/blackwithwhite666/OpenHarness@deploy"
systemctl --user enable --now ohmo-gateway.service worfalomey-token-refresh.timer
loginctl enable-linger blackwithwhite     # so user units run without an active login
```

## Secrets — NOT in this repo (live only in `$HOME` on the VM)

These files carry no inline secrets, but the running system depends on host-only state:
- `~/.kasmpasswd` — kasm web password (random, generated by `stage2a`; re-run prints a fresh one).
- `~/.openharness/settings.json`, `~/.codex/` — model/provider auth for the gateway.
- `~/.worfalomey_oauth.json` — worfalomey MCP OAuth tokens (refreshed by the timer).
- `~/.dropbox/` — Dropbox link state.
Provision these out-of-band after the run order above.
